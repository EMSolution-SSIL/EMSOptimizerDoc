# EMSOptimizer Concepts
This page introduces the core concepts used in EMSOptimizer.

## Overview
The following figure shows how the EMSOptimizer functions (hereafter, core objects) work together. The sequence ①→②→...→⑧ represents one iteration; optimization proceeds by repeating this sequence.  
:::info
Steps ②–⑦ are executed only for shape optimization (that is, when `evaluator` is `pyemsol_shape_evaluator`).  
These processes are included in the `emsopt_analyzer` package.
:::

## Core object implementation examples
EMSOptimizer provides ready-to-use implementation examples of its core objects.  
You can use the existing examples, modify them, or create new implementations and combine them freely. The implementations to use are specified in `optimization.yaml`.
:::info Related pages
- How to configure `optimization.yaml` → [User Guide > Optimization settings](../guides/optimization_config.md)
- Details and settings for each implementation example → corresponding sections in the User Guide
- How to create custom core objects → [Advanced Topics > Creating custom core objects](../advanced/user_define.md)
:::

### Optimizer
This object is responsible for the optimization algorithm (generating and updating candidate solutions). It receives candidate solutions evaluated by `evaluator`, generates new candidate solutions, and passes them to `evaluator`.

The following implementation examples in the `examples` folder are available.
- [`cmaes`](../guides/Optimizer/cmaes.md): Single-objective CMA-ES optimization algorithm \[4\], \[5\].
- [`nsga2`](../guides/Optimizer/nsga2.md): Multi-objective NSGA-II optimization algorithm \[6\].
- [`decomposition_ensemble`](../guides/Optimizer/decomposition_ensemble.md): MOEA/D-based multi-objective implementation example \[7\]. It decomposes multi-objective optimization into multiple single-objective problems, each solved by CMA-ES \[8\].

### Evaluator
This object is responsible for evaluating candidate solutions. It evaluates candidate solutions generated by `optimizer` (calculating objective and constraint function values) and returns the results to `optimizer`.  

The following implementation examples in the `examples` folder are available.
- [`sphere`](../guides/Evaluator/sphere.md): Single-objective Sphere benchmark function \[11\].
- [`rastrigin`](../guides/Evaluator/rastrigin.md): Single-objective Rastrigin benchmark function \[11\].
- [`zdt1`](../guides/Evaluator/zdt1.md): Multi-objective ZDT1 benchmark function \[9\].
- [`pyemsol_shape_evaluator`](../guides/Evaluator/pyemsol_shape_evaluator.md): **Evaluation implementation for shape optimization**. It analyzes shapes defined by `ls_function` and `ems_shape_builder` with the pyemsol electromagnetic simulator and calculates objectives and constraints defined in `optimization_problem.yaml` (for `optimizer_problem.yaml`, see [Optimization-problem settings](./opt_problem.md)).  
:::info
`pyemsol_shape_evaluator` is defined in the `emsopt_analyzer` package and has no implementation in the `examples` folder.  
The `emsopt_analyzer` package must be installed to run shape optimization with `pyemsol_shape_evaluator`.
:::
The `sphere`, `rastrigin`, and `zdt1` functions are optimization benchmarks that can be used to check `optimizer` performance before running shape optimization.

:::tip Shape optimization in EMSOptimizer
EMSOptimizer has no explicit “shape optimization mode.”  
Simply setting `evaluator` to `pyemsol_shape_evaluator` causes the relevant shape calculations to be performed internally.  
Therefore, shape optimization can be run in exactly the same way as benchmark-function optimization, although shape optimization requires `machine.yaml` and `optimization_problem.yaml` settings.
:::

### Level Set Function
This is the level set function used in topology optimization. It calculates the output of the level set function from the corresponding variables in a candidate-solution vector.  
When `evaluator` is set to `pyemsol_shape_evaluator`, it calculates function values at each location in the design target defined in `machine.yaml`. Material assignment is performed inside `pyemsol_shape_evaluator` based on these values.
:::info
In EMSOptimizer, a level-set function is any function that returns positive or negative values at each location in the design region (more precisely, at the center coordinates of each element).  
More generally, the term often refers specifically to a function used in the level-set method (a topology-optimization method) to represent material boundaries.
:::

The following implementation examples in the `examples` folder are available.
- [`ls_r`](../guides/LevelSetFunction/ls_r.md): Simple implementation that sets levels by radius.
- [`ngnet`](../guides/LevelSetFunction/ngnet.md): NGnet function \[3\].
- [`ngnet_mixture`](../guides/LevelSetFunction/ngnet_mixture.md): Implementation example combining `ls_r` and `ngnet` to apply NGnet within or outside a specified radius.
- [`ngnet_multi_material`](../guides/LevelSetFunction/ngnet_multi_material.md): Multi-material NGnet function \[3\].

### AnalysisConditioner
This object dynamically configures analysis conditions (such as the current phase angle and magnetization direction) for shape optimization. It is used when `evaluator` is set to `pyemsol_shape_evaluator` and changes analysis-condition parameters based on the corresponding variables in the candidate-solution vector.  
Thus, configuring this object makes it possible to include analysis conditions in the optimization.

The following implementation examples in the `examples` folder are available.
- [`phase_conditioner`](../guides/AnalysisConditioner/phase_conditioner.md): Changes the current phase angle.

### eMotorSolution Shape Builder
This object defines shapes for dimensional optimization. It can be used when `evaluator` is `pyemsol_shape_evaluator` and eMotorSolution integration is enabled; it sets motor component dimensions based on the corresponding variables in the candidate-solution vector.
:::info
For eMotorSolution integration, see [Advanced Topics > eMotorSolution integration](../advanced/link_ems.md).
:::

The following implementation examples in the `examples` folder are available.
- [`HoleMagnet55`](../guides/EMSShapeBuilder/holemagnet55.md): eMotorSolution HoleMagnet Type 55 permanent-magnet definition, used in the `IPM8P48S_pto` project.

:::tip Simultaneous optimization of analysis conditions, dimensions, and topology
In EMSOptimizer, `analysis_conditioner`, `ls_function`, and `ems_shape_builder` can all be configured independently and simultaneously. In particular, configuring `ems_shape_builder` together with `ls_function` enables simultaneous shape and topology optimization \[10\].  
More specifically, the candidate-solution vector is interpreted as follows.
```math
\boldsymbol{x} = [\boldsymbol{p}^\text{T}, \boldsymbol{d}^\text{T}, \boldsymbol{w}^\text{T}]^\text{T}
```
$\boldsymbol{x}$: candidate-solution vector  
$\boldsymbol{p}$: analysis-condition information vector passed to `analysis_conditioner`  
$\boldsymbol{d}$: shape-information vector passed to `ems_shape_builder`  
$\boldsymbol{w}$: level-set-function parameter vector passed to `ls_function`  
Among $\boldsymbol{p}$, $\boldsymbol{d}$, and $\boldsymbol{w}$, the vector corresponding to an unconfigured object is treated as a zero vector.
:::

:::tip Optimization control
`manager/optimization_manager.py` coordinates `evaluator` and `optimizer`.  
The `manager` folder also defines classes for GUI and file output, which are omitted here.
:::
