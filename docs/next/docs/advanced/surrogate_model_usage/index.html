サロゲートモデル導入

EMSOptimizerではv0.7.0より，サロゲートモデルによる最適化計算の高速化の実装例を公開しています。
このページではEMSOptimizerにおけるサロゲートモデル活用の詳細を説明します。

備考

実際の使用例についてはIPM8P48Sサロゲート利用例をご覧ください。

サロゲートモデル概要​

サロゲートモデル（または代理モデル，代替モデル）とは，電気機器の解析等の重い数値計算を代替するために構築されるモデルを指します。
有限要素法（FEM: Finite Element Method）は電気機器の解析に幅広く活用されていますが，その解析コストの高さが設計上のボトルネックとなることがあります。特に，最適化計算においては繰り返しFEMによる解析を行うため，この課題が顕著です。
サロゲートモデルはFEMの代替として，より軽量・高速に解析結果を再現するように構築するモデルです。既存のデータを機械学習モデルや深層学習モデルに学習させて解析結果を高精度に予測できるようにし，パラメータサーベイや最適化計算中のFEM解析を代替する手法が近年では盛んに活用されています。

活用フロー​

学習データの事前収集​

サロゲートモデルを構築するためには学習データが必要です。EMSOptimizerでは，optimization.yaml > output_control > candidate > enabledをTrueに設定することで，最適化過程において解析されたすべての個体のデータが蓄積されるようになります。
プロジェクト内における解析結果は各スタディの実行終了後，プロジェクト内summaryフォルダ > cross_studyフォルダ内のCSVファイルにまとめられます。また，個別の結果はsummaryフォルダ > optimization_studies内に保存されます。

オフライン学習とオンライン学習

サロゲートモデルを構築するには事前に学習データを収集することが一般的です。
一方，サロゲートモデルを最適化に用いる場合，最適化中に得られたデータによってサロゲートモデルを学習・更新する方法があります。一般に，最適化が進めば進むほど，サロゲートモデルも高精度化します。
ここでは前者をオフライン学習，後者をオンライン学習（または適応的学習）と呼称します。

オフライン学習を実施するためには上記の通り，学習データの事前収集が必要です。
オンライン学習は学習データの事前収集無でも実行可能です。しかし，事前収集した学習データを初期に与えることで，最適化の初めから高精度なサロゲートモデルによって解析結果の予測を行うことも可能です。

サロゲートモデルの最適化への組み込み​

EMSOptimizerでは，core.optimizer.surrogate_models内にサロゲートモデル実装を，core.optimizer.surrogate_utils内にサロゲートモデル利用のためのユーティリティを公開しています。
これらを利用した実装例としてsa_nsga2を公開しています。sa_nsga2ではdata_csv_path引数に事前収集した学習データへのパスを渡すことで，最適化実行前にサロゲートモデルの学習を自動的に実行します。また，enable_adaptive_training引数をTrueに設定することでオンライン学習が有効化され，最適化の毎世代の計算後にサロゲートモデルの更新を行います。

評価関数と設計変数の集約

summaryフォルダ内に保存されるCSVファイルにはユーザガイド > individual関連オブジェクト APIのIndivisualの情報が保存されます。
このうち，label_values（辞書型変数）のvalueは評価関数の生値を表すため，これをサロゲートモデルに学習させることでその予測結果を目的関数や制約条件として柔軟に組み替えて利用することが可能です。例えば，平均トルクを目的関数とした最適化を実施した後にその生値をサロゲートモデルに学習させ，その予測結果を今度は平均トルクを制約条件とする最適化問題に転用する，という運用が可能です。
なお，core.optimizer.surrogate_utils内のユーティリティには，サロゲートモデルによる予測結果をlabel_valuesのキー値が一致する箇所に自動的に格納する機能が実装されており，sa_nsga2内でもこの機能を利用しています。

一方，設計変数に関してはsolution_1, solution_2, ...のようにナイーブな列名で保存されます。そのため，設計変数の定義がスタディ間で変更された場合，cross_studyテーブルデータ上の設計変数の列に不整合が生じます。そのため，cross_studyテーブルデータを利用する場合は，スタディ間で設計変数の定義を統一することを推奨します。

応答曲面のGUI表示​

v0.7.0より、（広義の）応答曲面をGUIに簡易表示する機能を搭載しています。応答曲面により、どの設計変数が性能に効いているかを知ることができます。

備考

実際の設定例についてはIPM8P48Sサロゲート利用例をご覧ください。

  1. optimization.yaml > output_control > candidate > enabledをTrueに設定し、最適化を実行します。応答曲面はこの設定によって生成されるrun_records.csvを学習に使用します。
  2. optimization.yaml > response_surface > enabledをTrueに設定します。また、関連する設定を適当に設定します。設定の詳細はユーザガイド > 最適化の設定を参照してください。
  3. checkコマンドによってGUIを表示し、Response Srufaceタブを選択する。

下図に例を示します。上側のグラフは応答曲面、下側のグラフは設計変数の疑似的な重要度を示します。v0.7.0現在、重要度はランダムフォレストの特徴量重要度（feature_importance）として計算されます[35]。

  • Samplesは学習に使用されたサンプル数を示します。
  • Anchorは応答曲面表示の基準を示します。応答曲面は2軸に沿って表示され、設計変数が3以上の場合の非表示軸の値は基準の値に固定されます。
    • selected_individual: GUI上にて選択された個体の設計変数値。GUI上に選択個体がある場合、自動的にこちらの基準モードになります。
    • median_record: 学習データの平均値。選択個体が存在しない場合はこちらにフォールバックします。
  • 画面上部コンボボックスからは、表示する値（性能値）、応答曲面表示の横軸・縦軸を選択できます。
